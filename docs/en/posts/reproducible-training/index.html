Leave Enough Behind to Reproduce the Next Training Run

A seed is only the beginning. Keep configurations, data splits, checkpoints, and experiment records together.

PyTorchReproducibility

Sample article · Written to demonstrate the reading layout; not an original publication by the author.

Reproducing a training result usually takes more than a seed. Data versions, the actual folds, preprocessing, package versions, and checkpoint selection all affect how we interpret an experiment.

Give each experiment its own directory

text
runs/experiment_001/
  config.json
  split.csv
  environment.txt
  train.log
  metrics.csv
  checkpoints/
    best.pt
    last.pt

Keep best and last checkpoints separately

Select the best checkpoint using a predefined validation metric. Use the last checkpoint to resume interrupted training. Resuming may require the optimizer, scheduler, AMP scaler, epoch, and random states in addition to model weights.

  • Record batch size, gradient accumulation, and mixed-precision settings in the configuration.
  • Document the monitored metric, direction, and patience for early stopping.
  • Write training and validation metrics for every epoch, keeping failure records.
  • Reserve the test set for a fixed evaluation procedure once the experiment design is settled.

Different hardware and computational implementations may still introduce nondeterminism. Rather than promising identical runs everywhere, record the environment, control known variables, and describe variability through repeated experiments.
